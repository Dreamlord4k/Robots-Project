# Robots-Project: Оптимальное производство и продажа роботов

Учебный проект-MVP для соревнования по оптимизации. Реализует жадную стратегию на основе метрики «прибыль в минуту», эмулятор событий и веб-панель мониторинга.

## Статус проекта

- **Ядро и данные:** реализовано, вынесено в JSON-конфиги.
- **Стратегия и эмулятор:** в разработке (следующий этап).
- **Веб-панель:** готова к подключению результатов (ожидает `results.json`).
- **Старый прототип («Робот Планер»):** перемещён в папку `src/OldPlanner`. Оставлен для регрессионных проверок и валидации расчётов. Не используется в текущей сборке.

### Вариант 1: Через Visual Studio / VS Code (рекомендуется)

1.  Откройте папку проекта в редакторе.
2.  Убедитесь, что в терминале выбран профиль `.NET 8`.
3.  Запустите эмулятор:
    ```bash
    dotnet run --project src/Emulator
    ```
4.  Эмулятор начнёт работать в режиме «быстрого прогона» раунда. В консоли будут появляться логи событий: поставки, запуск станков, продажи, отказы.
5.  По окончании раунда в папке `site/data/` появится файл `results.json` (если путь указан верно в `config.json`).
6.  Откройте `site/index.html` в браузере, чтобы увидеть панель мониторинга с результатами.

### Вариант 2: Публикация на GitVerse Pages

1.  Закоммитьте все файлы.
2.  В настройках репозитория на GitVerse включите Pages, выбрав ветку `master` и папку `/site`.
3.  После сборки (1–2 минуты) откройте ссылку на сайт. Панель будет автоматически подгружать `data/results.json`.
    > **Важно:** Для работы панели нужен файл `results.json`. На пустой странице без данных панель покажет заглушки. Чтобы увидеть реальную картину, сначала запустите эмулятор локально, получите JSON, закоммитьте его и только потом проверяйте сайт.

## Экономика и стратегия

Проект использует жадно-приоритетный алгоритм:

1.  **Приоритет роботов:** Рассчитывается как `Прибыль / Время производства`. В первую очередь запускаются роботы с наибольшей прибылью в минуту.
2.  **Склад:** Принятие поставки зависит от `MaxWarehouseFillRatio`. Если склад заполнен более чем на 80% (значение из `config.json`), поставка отклоняется.
3.  **Продажа:** Робот предлагается покупателям в порядке убывания цены. Если покупатель отклоняет сделку (с вероятностью `AcceptChance`), робот предлагается следующему.
4.  **Переналадка:** Если станок уже настроен на тип робота, время переналадки равно 0. Это создаёт выгоду от запуска партий однотипных роботов.

Все параметры экономики (цены, время, лимиты) вынесены в папку `data/`. Чтобы изменить сложность или доходность, достаточно отредактировать JSON-файлы, не меняя код.

## Как вносить изменения и делать коммиты

Мы придерживаемся принципа «маленькие коммиты — большой прогресс»:

-   `feat(data): добавить ...` — новые JSON-конфиги.
-   `feat(core): добавить модель ...` — новые классы-модели.
-   `feat(strategy): реализовать ...` — новая логика стратегии.
-   `fix: ...` — исправление ошибок.
-   `docs: ...` — обновление документации.

Такой подход позволяет легко откатиться назад, если что-то пойдёт не так, и показать ревьюеру чёткую историю изменений.

## Технические детали

-   **Язык:** C# (.NET 8)
-   **Формат данных:** JSON
-   **Сериализация:** `System.Text.Json` (встроенный в .NET)
-   **Перечисления в JSON:** Операции (`Cutting`, `Painting` и т.д.) сохраняются как строки. Для корректного чтения обязательно использовать `JsonStringEnumConverter`.
