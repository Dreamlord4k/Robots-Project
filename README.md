# Завод роботов

HTTP-сервис команды для арены «Завод роботов», локальный эмулятор и экспериментальный стенд. Арена вызывает сервис; параметры смены приходят в `start`. Проверенная среда — Node.js v24.20.0; внешние зависимости не нужны. Исходные документы организаторов находятся в `docs/specification-v1.txt` и `docs/openapi-v1.yaml`.

## Запуск

```sh
PORT=4001 node src/server.mjs
```

По умолчанию используется порт 8080. `GET /v1/health` возвращает `{"status":"ok"}`; арена отправляет `POST /v1/runs/{runId}/start`, затем события на `/event` и итог на `/finish`. Повтор события с тем же `seq` возвращает сохранённый ответ; состояния покупателей разных `runId` независимы. После `finish` состояние бота освобождается. Сервер отвечает на CORS preflight, включая заголовок для доступа к частной сети. Локальная конфигурация разрешает любое происхождение и не проверяет Bearer-токен; публичный доступ и защиту нужно настраивать отдельно.

## Стратегия

Рабочая версия — S04: `src/bot.mjs` и `src/s04-planner.mjs`. База до улучшений сохранена в `experiments/baseline-bot.mjs`. В смене бот строит шесть гипотез покупателя по цвету и ручкам. Диапазоны Pmax 45–75 и f 0,30–0,60, равные веса гипотез и оценка по серединам интервалов — предположения v1; `priceCeiling` учитывается из `start`. Шум ±2% и консервативный запас на округление допускают пересечение ценовых ступеней: по порогу 44 нельзя однозначно определить тип. Отказ учитывается только при известном `minPrice` и причине `below_min_price`, cooldown не является ценовым наблюдением. Если в `sale_result` нет необязательного `item`, используется сохранённый предмет текущего предложения. Противоречивое наблюдение не стирает предыдущую модель.

Производственный планировщик использует фактические операции и длительности из `start`, текущий снимок склада и станков, известные оценки покупателей и оставшееся время. Он ограничивает число кандидатов и глубину прогноза, учитывает резерв места и не предполагает фактические будущие поставки. При исчерпании бюджета возвращает пустой производственный план; другие допустимые действия могут выполняться. Ограничение времени кооперативное и не прерывает поток при задержке ОС. Перед реальным раундом требуется проверить задержку с сетью и официальным стендом. Поддержка других наборов свойств и произвольных производственных цепочек не заявляется.

В отложенном локальном наборе из 500 миров сохранённая экспериментальная S04 относительно базы дала среднюю парную разницу +677,76 и медиану +523,62; выиграла в 384 мирах и проиграла в 116. После оценки рабочие файлы изменились, поэтому эти показатели к ним неприменимы. Эмулятор не сверялся с официальным движком. Подробности и ограничения — в `experiments/s05-report.md`.

## Проверки и эксперименты

```sh
node --test tests/s05-report.mjs tests/s04-planner.mjs tests/s04-integration.mjs tests/s04-comparison.mjs tests/s03-sales.mjs tests/buyer-model.mjs tests/experiment.mjs tests/metrics.mjs
node tests/test.mjs
node tests/arena-http.mjs
node tests/server-robustness.mjs
node tests/s04-http.mjs
node cli.mjs --seeds 20 --verbose
```

HTTP-тестам нужен доступ к локальному порту. `cli.mjs` — локальный бенчмарк, не официальный симулятор. Методика и файлы настройки и оценки находятся в `experiments/`; единичная отложенная оценка защищена от случайного повторного запуска. Официальный API-check и повторный прогон официальной песочницы в этой работе не выполнялись.
