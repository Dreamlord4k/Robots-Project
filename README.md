# Завод роботов

Сервис для арены «Завод роботов»: принимает события смены, управляет производством и предлагает готовых роботов покупателям. В проект входят локальный эмулятор, бенчмарк и веб-дашборд.

Арена вызывает сервис по HTTP. На каждое событие бот получает снимок фабрики и возвращает список команд; их выполнение и расчёт прибыли остаются за ареной.

## Быстрый старт

Требуется **Node.js 18 или новее**. Внешние зависимости не нужны.

```sh
npm start
```

Сервис запустится на порту `8080`. Проверить его работу:

```sh
curl http://localhost:8080/v1/health
```

Ожидаемый ответ: `{"status":"ok"}`. Дашборд доступен по адресу [http://localhost:8080/](http://localhost:8080/).

Чтобы изменить порт или отключить дашборд:

```sh
PORT=4001 npm start
ENABLE_DASHBOARD=0 npm start
```

При отключённом дашборде API арены продолжает работать.

## Как работает стратегия

Покупатели скрывают свои предпочтения по цвету и наличию ручек. Бот ведёт для каждого покупателя шесть возможных вариантов предпочтений и уточняет их по продажам и отказам. Информация о покупателях хранится отдельно для каждого прогона.

На основе текущего склада, занятости станков, оценок покупателей и оставшегося времени бот:

1. Решает, принимать ли поставку сырья.
2. Планирует резку, установку ручек, покраску и сборку.
3. Подбирает пары «робот — покупатель» и минимальную цену предложения.
4. Освобождает место от роботов, которые по его оценке не востребованы.

Планировщик использует операции и их длительности из `start`. Он ограничивает число рассматриваемых вариантов и не опирается на будущие поставки. Если бюджет поиска исчерпан, бот может продолжить продажи без новых производственных команд.

## API арены

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/v1/health` | Проверка доступности сервиса |
| `POST` | `/v1/runs/{runId}/start` | Начало прогона и передача его параметров |
| `POST` | `/v1/runs/{runId}/event` | Событие смены и получение команд |
| `POST` | `/v1/runs/{runId}/finish` | Завершение прогона |

Сервис обрабатывает события поставки, завершения операции, результата продажи и ожидания. Повтор события с тем же `runId` и `seq` возвращает сохранённый ответ. Снимок состояния предшествует командам в ответе; команды выполняются последовательно, не более 50 за событие.

## Проверки и локальная симуляция

```sh
npm test             # тесты бота, планировщика и эмулятора
npm run test:http    # HTTP-контракт и устойчивость сервера
npm run test:all     # все перечисленные проверки
```

HTTP-тестам необходим свободный локальный порт. Для сравнения стратегий в локальном эмуляторе:

```sh
node cli.mjs --seeds 20 --verbose
```

Опция `--horizon` задаёт длительность смены в тактах; по умолчанию используется 650.

## Ограничения

- Эмулятор не сверен с официальным движком. Результаты локальных прогонов не гарантируют прибыль на арене.
- Текущая стратегия рассчитана на шесть типов роботов и производственную цепочку v1; произвольные новые свойства и операции не поддерживаются.
- Лимит времени планировщика проверяется внутри процесса и не учитывает сетевую задержку.
- Локальный сервер разрешает CORS и не проверяет Bearer-токен. Для публичного доступа защиту необходимо настроить отдельно.
